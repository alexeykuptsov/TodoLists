# Подведём итоги

Скилл разбирает прошедшую сессию и аккуратно переносит новые знания в `AGENTS.md`, папку `docs/` и систему памяти Claude.
Файлы не раздуваются — остаётся лишь то, что проверено и будет нужно в следующих сессиях.

## Принципы

- Лучше обновить одну строку, чем дописать абзац
- Не фиксировать текущее состояние работы — только выводы
- Не дублировать то, что читается прямо из кода или git-логов

### Правило трёх вопросов

Перед тем как сохранить факт, ответь на три вопроса. Если хоть один ответ — «нет», факт **не записывается**:

1. **Подтверждено?** Факт следует из живого кода, реального запуска, вывода инструмента или git-истории — не из предположений или памяти по умолчанию.

2. **Пригодится позже?** Это будет полезно в будущих задачах, а не только сейчас. Временные состояния («пока делаем X», «на время включили Y») — не сохраняем.

3. **Не очевидно из кода?** Если любой разработчик сам найдёт это /в файлах — дублировать не нужно.

Дополнительно исключаем:

- Детали задачи текущего момента
- Секреты и чувствительные данные
- Общеизвестные факты о стеке или языке

### Типичные ошибки

- Добавлять новые абзацы там, где достаточно обновить строку
- Записывать in-progress состояние вместо итогов
- Копировать то, что уже есть в коде

## Инструкции

Выполняй шаги строго по порядку.

### 1. Извлеки знания из диалога

Просмотри переписку и выдели:

- **Факты о проекте** — структура, зависимости, архитектурные решения, не видные из кода
- **Конвенции** — как называть, форматировать, организовывать
- **Предпочтения пользователя** — стиль взаимодействия, что устраивает и что нет
- **Обратная связь** — поправки, подтверждения нетривиальных решений

Пропускай то, что уже зафиксировано в `knowledge-base/` или памяти, и то, что очевидно из кода.

### 2. Прочитай актуальное состояние файлов

Прежде чем вносить изменения, прочитай:
- `AGENTS.md` и нужные файлы в `docs/`
- Файлы памяти, которые планируешь обновить

### 3. Запиши в AGENTS.md и/или docs/

Добавляй напрямую в `AGENTS.md` или в файлы папки `docs/`.

Старайся не увеличивать `AGENTS.md` — если нужно место, перенеси что-то менее важное в `docs/`.

Для каждого нового факта о **проекте**:
- Найди подходящий файл в `docs/` и дополни его
- Если подходящего нет — создай с говорящим именем
- Один факт — одна строка или короткий абзац
- Не дублируй уже записанное
- Файл должен быть достижим из `AGENTS.md` по цепочке ссылок

### 4. Запиши в память Claude

**Предпочтения и обратную связь** сохраняй в `.claude\memory\`:

Формат файла:
```markdown
---
name: <kebab-case-slug>
description: <одна строка — критерий релевантности>
metadata:
  type: <user | feedback | project | reference>
---

<содержимое>

**Why:** <причина>
**How to apply:** <когда применять>
```

Обновляй существующие файлы, если подходят. Новый файл — только при отсутствии подходящего. Не забудь обновить `MEMORY.md` — одна строка на файл.

### 5. Отчёт

Выведи краткую сводку:

```
Сохранено:
• knowledge-base/xxx.md — [что добавлено]
• memory/xxx.md — [что добавлено]

Намеренно отброшено: [что уже было известно или не стоит хранить]
```

Если сохранять нечего — напиши: «В этой сессии новых фактов для сохранения нет.»
